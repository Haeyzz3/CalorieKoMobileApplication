# Dish Recipes Regeneration Implementation Plan

## Summary

Regenerate `app/src/main/assets/dish_recipes.json` from the corrected ingredient nutrient data in `app/src/main/assets/raw_ingredients.json`, so dish-level Vitamin A values use RAE micrograms instead of obsolete IU-scale values.

This is a dish-level follow-up to the ingredient USDA pipeline refactor. The ingredient source file is now corrected, but any dish nutrient totals previously computed from the old ingredient values remain stale.

`recipe_ingredients.json` should not be regenerated by default because it stores recipe composition and raw ingredient weights, not nutrient values. It should only be modified if a preflight inspection finds that the current dish generator cannot recompute `dish_recipes.json` without also rewriting recipe ingredient rows.

## Goals

- Recompute dish nutrient fields from the corrected `raw_ingredients.json`.
- Preserve dish metadata that is not derived from ingredient nutrients.
- Avoid changing recipe composition, ingredient weights, servings, yield factors, names, categories, and serving descriptions unless a mismatch is explicitly found and approved.
- Keep the work scoped to dish data. Do not revisit the ingredient USDA pipeline unless a blocker is found.
- Do not run any Gradle commands.

## Current State

- `raw_ingredients.json` now stores Vitamin A as `µg RAE`.
- `dish_recipes.json` still contains stale dish nutrient totals from the old ingredient values.
- Egg-derived dishes are known stale examples:
  - A 50 g egg currently contributes `270` Vitamin A in dish data, which came from `540 IU / 100 g`.
  - With corrected `160 µg RAE / 100 g`, a 50 g egg should contribute about `80 µg RAE`.
- `recipe_ingredients.json` contains ingredient keys, raw weights, original portions, preparation methods, and ingredient types. It does not store nutrient values.

## Scope

In scope:

- `app/src/main/assets/dish_recipes.json`
- Existing dish generation/calculation scripts, especially `scripts/generate_dish_jsons.py`
- Validation or audit scripts needed to compare before/after dish nutrient values
- Documentation of changed dish nutrient outputs

Out of scope:

- `raw_ingredients.json`, except read-only input
- USDA ingredient fetch/refactor work
- `recipe_ingredients.json`, unless preflight proves regeneration is unavoidable
- Room schema migrations
- Gradle, Android build, or emulator validation

## Implementation Steps

### 1. Preflight Inspection

Before changing generated files, inspect the current generator behavior.

- Read `scripts/generate_dish_jsons.py`.
- Confirm whether it rewrites both `recipe_ingredients.json` and `dish_recipes.json` in one run.
- Identify which fields are computed versus preserved:
  - Computed: `total_nutrients_raw`, `per_serving_nutrients`
  - Usually computed or preserved: `total_raw_weight_g`, `cooked_weight_g`, `per_serving_weight_g`
  - Preserve unless intentionally recomputed: `servings`, `dish_yield_factor`, `serving_size_description`, names, categories, cooking method
- Confirm how store-bought/manual/simple dishes are represented.
- Decide whether to use the existing generator directly or write a narrow dish-nutrient-only refresh script.

Recommended default:

- Prefer a narrow refresh script if the existing generator would rewrite `recipe_ingredients.json` or alter non-nutrient dish fields.
- Use the existing generator only if a dry-run diff shows it changes only the intended nutrient fields.

### 2. Create a Safe Dish Nutrient Refresh Path

Implement or adapt a script that:

- Loads `raw_ingredients.json`.
- Loads existing `recipe_ingredients.json`.
- Loads existing `dish_recipes.json`.
- Builds an ingredient nutrient lookup by `ingredient_key`.
- Groups recipe ingredient rows by `dish_label`.
- Recomputes nutrient totals using:
  - `raw_weight_grams / 100 * ingredient.nutrients_per_100g[nutrient]`
  - Existing oil absorption logic if the current dish pipeline applies it
  - Existing dish-specific cooking/yield conventions only if already part of nutrient calculation
- Updates only these fields in each affected dish:
  - `total_nutrients_raw`
  - `per_serving_nutrients`
- Keeps all non-nutrient fields byte-for-byte equivalent where practical.

Important caveat:

- Do not recompute `recipe_ingredients.json` as part of this pass unless the team explicitly decides to refresh recipe weights too. Changing weights would expand the blast radius from nutrient correction to recipe definition changes.

### 3. Preserve Special Cases

Handle these cases explicitly:

- Dishes with no matching recipe rows:
  - Preserve as-is.
  - Log them as skipped.
- Store-bought dishes:
  - Preserve as-is unless they are intentionally modeled from `recipe_ingredients.json`.
- Manual/simple dishes with hardcoded nutrient blocks:
  - Preserve as-is unless their ingredients are present in `recipe_ingredients.json` and the existing app expects them to be computed.
- Missing ingredient keys:
  - Fail the script instead of silently writing partial nutrient values.
- Zero-weight ingredients:
  - Keep them in `recipe_ingredients.json`; they contribute zero nutrients.

### 4. Expected Data Changes

The primary expected change is lower Vitamin A for dishes previously inflated by IU-scale ingredient values.

Known examples to verify:

- `egg_sunny`
- `egg_boiled`
- `egg_omelette`
- `egg_scrambled`
- `kwekwek`
- `egg_ampalaya`

Expected egg-only rough check:

- One 50 g egg should contribute about `80 µg RAE` Vitamin A.
- If the dish also includes oil or other ingredients, only non-egg ingredients should add additional Vitamin A.

Other vegetable-heavy dishes should also change because ingredients such as carrot, tomato, squash, leafy greens, and peas were previously IU-scale in `raw_ingredients.json`.

### 5. Validation

Run Python-only checks.

Required checks:

```powershell
python tools\validate_json.py
```

Add or run a dish validation script that confirms:

- Every dish still has all required nutrient keys.
- `total_nutrients_raw` equals the sum of recipe ingredient contributions within a small tolerance.
- `per_serving_nutrients` equals `total_nutrients_raw / servings` within a small tolerance.
- No dish has missing metadata fields after regeneration.
- `recipe_ingredients.json` is unchanged unless explicitly approved.

Targeted spot checks:

- Egg-only dishes no longer show `270` Vitamin A per serving.
- `egg_boiled` should be approximately `80 µg RAE` if it is one 50 g egg and no nutrient-bearing additions.
- `chicken_egg` contribution should use `160 µg RAE / 100 g`.

Static checks:

```powershell
rg -n "Vitamin A \\\\(IU\\\\)| IU|1104.*vitamin_a|vitamin_a.*1104" scripts tools app/src/main/java
```

Expected result:

- No active IU Vitamin A mapping or ingredient/dish display label should be found.

Do not run:

```powershell
.\gradlew
gradle
```

### 6. Review Diff Before Finalizing

Inspect the generated diff carefully.

Acceptable changes:

- `dish_recipes.json`
  - `total_nutrients_raw`
  - `per_serving_nutrients`
- Optional script changes needed for safe regeneration or validation
- Optional documentation/audit output

Unexpected changes that should stop the task:

- `recipe_ingredients.json` changed without prior approval
- Dish names, labels, servings, yield factors, cooked weights, or serving descriptions changed unexpectedly
- `raw_ingredients.json` changed
- Any Gradle-generated or Android build files changed

### 7. Final Handoff Summary

The final implementation report should include:

- Whether `recipe_ingredients.json` was unchanged.
- Number of dishes recomputed.
- Number of dishes preserved or skipped.
- Before/after Vitamin A values for representative dishes:
  - `egg_boiled`
  - `egg_sunny`
  - `egg_ampalaya`
  - one vegetable-heavy dish such as `pinakbet` or `chopseuy`
- Python validation commands run.
- Confirmation that no Gradle commands were run.

## Acceptance Criteria

- `dish_recipes.json` nutrient totals are derived from corrected `raw_ingredients.json`.
- `recipe_ingredients.json` remains unchanged unless explicitly approved.
- Egg-only dishes no longer show old IU-scale Vitamin A values.
- Validation confirms all dish nutrient keys are present and internally consistent.
- Static search finds no active IU Vitamin A mapping/display regressions.
- No Gradle command is run.
